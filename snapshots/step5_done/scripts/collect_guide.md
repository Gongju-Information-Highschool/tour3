# A2 — 네이버플레이스 수집 절차 (교사용, 약 3시간)

> **이 문서가 지금 이 프로젝트에서 유일하게 남은 사람 손 작업입니다.**
> 코드는 전부 완성되어 있고 검증도 통과합니다. 지금 들어 있는 별점·리뷰수만
> 임시값(placeholder)입니다. 이 문서대로 실제 값을 채우면 프로젝트가 끝납니다.

기획안 §4.1 · §8 A2에 해당합니다.

---

## 0. 지금 상태

| 항목 | 상태 |
|---|---|
| 장소명 30곳 | **실제** (v2.4에서 이어받음, 네이버 지역검색으로 실재 확인된 곳) |
| 좌표 (lat/lon) | **실제** (`data/spots_geo.csv`, 네이버 mapx/mapy ÷ 10⁷) |
| 별점 · 방문자리뷰 · 블로그리뷰 | **임시값** ← 이 문서가 채울 대상 |
| 도로명주소 | 임시값("충청남도 공주시") ← 함께 채우면 좋음 |
| 카테고리 원문 | 그럴듯하게 채워 둠 ← 실제 화면 문구로 교체 권장 |

임시값으로 돌고 있다는 사실은 화면 상단 배너·`init_db.py` 출력·`verify.py` 결과에
모두 표시됩니다. 숨겨지지 않으니 학생에게 잘못 알려질 일은 없습니다.

## 1. 무엇을, 어디서 가져오나

별점과 리뷰 수는 **지역검색 API가 주지 않습니다.** 두 곳을 합쳐야 합니다.

| 출처 | 가져올 값 |
|---|---|
| 네이버 **지역검색 결과** | 장소명, 도로명주소, 카테고리 원문, `mapx` / `mapy` |
| 네이버 **플레이스 페이지** | 별점, 방문자리뷰 수, 블로그리뷰 수, (확장 1용) 영업시간 |

좌표는 이미 있으므로 **다시 수집하지 않아도 됩니다.** (약 1시간 절약)

### 지켜야 할 선

- 사람이 화면을 보고 옮겨 적는 **수기 수집**입니다. 자동 크롤러를 돌리지 않습니다.
- 교육 목적 내부 실습용이며 **재배포하지 않습니다.**
- 화면에 출처와 수집 시점을 반드시 표기합니다 (`base.html`이 자동으로 표시합니다).

## 2. 순서

### ① 카테고리 분포부터 손본다 (가장 중요)

지금 30곳의 분포는 이렇습니다.

```
역사문화 11 · 자연 4 · 체험 4 · 먹거리 4 · 카페감성 2 · 휴식 5
```

**카페감성이 2곳뿐이라 필터 칩 하나가 거의 빈 화면이 됩니다.**
카테고리 필터는 이 서비스의 첫 상호작용인데, 눌렀더니 마커가 2개면
학생은 기능이 고장 났다고 생각합니다. `verify.py` 2번이 이 때문에 `[ ? ]` 상태입니다.

- 네이버 지역검색에서 **"공주 카페", "공주 디저트"** 로 검색해
  주소가 `충청남도 공주시`로 찍히는 곳 **3곳**을 고릅니다.
- 역사문화 11곳 중 성격이 겹치는 **3곳**을 뺍니다.
  권장: 사찰 4곳(마곡사·갑사·동학사·신원사) 중 1곳 + 박물관 계열 2곳.
  사찰을 다 빼지는 마세요 — 원도심에서 멀리 떨어진 곳이 있어야
  거리 점수(§5.3)와 동선의 차량 구간(§5.6)이 눈에 보입니다.
- 목표: **모든 분류가 4곳 이상.**

> 계룡시·논산시 소재가 검색 결과에 섞여 나옵니다. 주소를 반드시 확인하세요.

### ② 30곳의 플레이스 페이지를 열어 값을 옮겨 적는다

장소 하나에 약 3~4분, 30곳이면 두 시간 안쪽입니다.

`data/places_raw.csv` 를 Excel이 아니라 **메모장이나 VS Code로** 엽니다.
(Excel로 열어 저장하면 한글이 깨집니다 — 이 프로젝트에서 가장 흔한 사고입니다)

컬럼은 아래 그대로 둡니다.

| 컬럼 | 채울 값 |
|---|---|
| `name` | 플레이스 상호 그대로 |
| `category_raw` | 플레이스 화면에 뜨는 분류 문구 그대로 (예: `사찰`, `베이커리`) |
| `road_address` | 도로명주소 |
| `mapx` / `mapy` | 이미 채워져 있음 (건드리지 않음) |
| `star` | 별점. **없으면 빈칸으로 둡니다** ← 결측이 곧 교재입니다 |
| `visitor_rev` | 방문자리뷰 수 |
| `blog_rev` | 블로그리뷰 수 |
| `collected_at` | 수집한 달 (예: `2026-08`) |

**화면에서 복사하면 1,000 이상은 `"1,204"` 처럼 콤마가 붙습니다. 그대로 두세요.**
콤마를 지우는 것이 학생의 Step 2 실습입니다.

### ③ 오염 3종을 유지한다 (33행 만들기)

정제 실습이 성립하려면 원본이 33행이어야 합니다.

| 오염 | 방법 |
|---|---|
| 중복 2행 | 같은 가게를 표기만 바꿔 한 줄씩 더 넣습니다 (`개성집` / `개성집공주점`, `공주 산성시장` / `공주산성시장`). 리뷰 수는 **원본보다 적게** 적어 원본이 살아남게 합니다 |
| 좌표 결측 1행 | 관광지가 아닌 검색 결과(예: `공주역`)를 넣고 `mapx`/`mapy`를 비웁니다 |
| 별점 결측 5행 | 실제로 별점 없는 곳을 5곳 고릅니다. 억지로 지우지 말고 진짜 없는 곳으로 |

정제 정답이 **33행 → 30행**이 되어야 `verify.py` 0번이 통과합니다.

### ④ 카테고리 매핑표를 채운다

수집한 `category_raw` 원문이 `data/category_map.csv` 에 없으면
`preprocess.py` 가 오류 대신 **없는 원문 목록을 출력**합니다. 그것을 보고 한 줄씩 추가하면 됩니다.

> 매핑은 **원문 단위**입니다. `미술관`이라는 원문 하나는 한 분류로만 갑니다.
> 장소마다 다른 분류를 주고 싶으면 `category_raw`를 더 구체적으로 적으세요
> (실제 네이버 분류도 `미술관` / `갤러리` / `전시관`처럼 나뉘어 있습니다).

### ⑤ params.json 을 확정한다

```bash
python scripts/preprocess.py
python scripts/init_db.py --reset
```

`init_db.py` 가 **별점 실측 평균**을 찍어 줍니다.
`data/params.json` 의 `c_mean` 과 0.05 이상 차이 나면 **적재를 멈춥니다.**

- 차이가 크면 `c_mean` 을 실측 평균(소수 둘째 자리)으로 고칩니다.
- 그다음 손계산 예제 두 곳을 **실제 데이터에서** 고릅니다.
  - 하나는 *리뷰가 아주 적고 별점이 높은 곳* (예: 리뷰 2개, 5.0점)
  - 하나는 *리뷰가 아주 많고 별점이 보통인 곳* (예: 리뷰 312개, 4.4점)
  - 두 곳의 보정 별점을 계산해 `hand_calc` 의 `expect` 에 소수 둘째 자리로 적습니다.
- 마지막으로 `data_source` 를 `"placeholder"` → `"naver_place"` 로 바꿉니다.
  이 순간 화면 상단 배너가 임시 데이터 경고에서 출처 표기로 바뀝니다.

> **⑤가 끝나기 전에 교재를 인쇄하지 마세요.**
> 교재에 인쇄된 손계산 정답과 코드 출력이 어긋나면 §10 검증 4번이 영구히 실패합니다.

### ⑥ 검증

```bash
python scripts/verify.py
```

13항목이 전부 `[ O ]` 여야 합니다. 특히 두 가지를 보세요.

- **2번**이 `[ ? ]` 에서 `[ O ]` 로 바뀌었는가 → ①을 제대로 했는가
- **5번**(순위 3계단 이상 변동 3곳)이 통과하는가 → 실데이터로도 데모가 성립하는가

5번이 실패하면 별점·리뷰수 분포가 밋밋한 것입니다.
**리뷰가 아주 적고 별점이 높은 곳**을 몇 곳 더 넣으면 해결됩니다
(작은 카페·갤러리는 실제로 리뷰 10개 미만에 별점 4.8~5.0인 경우가 흔합니다).
이건 수업 당일에는 고칠 수 없으니 **반드시 전날 이전에** 확인하세요.
