# 공주 지도 탐색 서비스 "맵으로 공주" — 개발기획안 (v1.0)

> **대상**: 고등학교 경영정보 전공 학생 (개발 입문자)
> **포지션**: 『AI 관광추천 v2.4』의 **자매 프로젝트** — 같은 지역(공주시 30곳), 완전히 다른 UI·데이터·알고리즘
> **원칙**: 내부 DB(SQLite) + 로컬호스팅 + 단일 폴더 유지. 단, **지도 UI를 위해 Leaflet 1개만 예외 허용**
> **데이터**: **네이버플레이스 정보를 사전 수집한 CSV** (별점·방문자리뷰수·블로그리뷰수·카테고리·좌표) — 수업 중 API 호출 없음, 오프라인 안전
> **확정 환경**: Python 3.13 (Windows) · Flask · SQLite · Leaflet(로컬 번들)
> **작성일**: 2026-08-30

## 1. 프로젝트 한 줄 정의

지도를 열고 → 마커를 눌러 네이버플레이스 정보를 보고 → 마음에 드는 곳을 찜하면,
**보정 별점·거리·내 클릭 패턴**으로 장소를 다시 줄 세워 주고 찜 목록을 **걷기 좋은 순서의 동선**으로 정렬해 주는 웹 서비스.

이 프로젝트가 학생에게 남겨야 하는 것은
**"리뷰 수가 다른 별점을 공정하게 비교하는 방법(베이지안 보정)을 손으로 계산해 설명할 수 있는 상태"** 다.

## 4. 데이터 설계 — 네이버플레이스가 원천

### 4.1 수집 항목 (교사 사전 수집, `collect_guide.md`)

네이버플레이스 화면에서 30곳에 대해 아래를 수집한다.
**지역검색 API는 별점·리뷰수를 주지 않으므로**, 좌표(mapx/mapy)·주소·카테고리 원문은 지역검색 결과에서,
별점·방문자리뷰수·블로그리뷰수는 플레이스 페이지에서 교사가 수집해 CSV로 만든다.
수집일을 CSV에 기록한다 — 리뷰 수는 살아 있는 숫자이므로 "2026-08 기준 스냅샷"임을 수업에서 명시한다.

### 4.2 테이블 4개 (확정 스키마)

```sql
CREATE TABLE places (
  id            INTEGER PRIMARY KEY,
  name          TEXT NOT NULL,
  category_raw  TEXT NOT NULL,   -- 네이버 원문. 예: '사찰', '베이커리', '박물관'
  category      TEXT NOT NULL,   -- 표준 6분류 (역사문화·자연·체험·먹거리·카페감성·휴식)
  road_address  TEXT,
  lat           REAL NOT NULL,   -- mapy ÷ 10^7
  lon           REAL NOT NULL,   -- mapx ÷ 10^7
  star          REAL,            -- 네이버 별점 (없는 곳은 NULL — 실제로 흔함)
  visitor_rev   INTEGER NOT NULL,-- 방문자리뷰 수
  blog_rev      INTEGER NOT NULL,-- 블로그리뷰 수
  collected_at  TEXT NOT NULL    -- 수집일
);

CREATE TABLE users (             -- v2.4와 동일 개념, session 기반
  id INTEGER PRIMARY KEY, nickname TEXT, created_at TEXT
);

CREATE TABLE clicks (            -- ★ 암묵 피드백 로그
  id INTEGER PRIMARY KEY, user_id INTEGER, place_id INTEGER,
  action TEXT,                   -- 'view'(패널 열람) | 'fav'(찜) | 'unfav'
  created_at TEXT
);

CREATE TABLE favorites (
  id INTEGER PRIMARY KEY, user_id INTEGER, place_id INTEGER, created_at TEXT
);
```

### 4.3 표준 카테고리 6분류 — 순서 고정

```
역사문화(0) · 자연(1) · 체험(2) · 먹거리(3) · 카페감성(4) · 휴식(5)
```

네이버 카테고리 원문은 '사찰', '문화유적', '베이커리', '박물관' 등 제각각이다.
`category_map.csv`가 원문→표준 매핑을 담당하며, **매핑표를 채우는 것 자체가 Step 2 실습**이다.
(v2.4의 '테마 표기 통일'과 같은 학습 목표를, 이번엔 실데이터의 실제 다양성으로 수행)

### 4.4 원본 CSV는 일부러 — 그리고 실제로 — 지저분하다 ★

네이버플레이스 수집 데이터는 오염을 "주입"할 필요가 거의 없다. **실데이터가 원래 지저분하다.**
정제 기준 30행에 아래를 반영해 원본 33행을 만든다.

| 오염 유형 | 건수 | 내용 | 출처 |
|---|---|---|---|
| 중복 행 | 2 | 같은 장소가 지점명 표기 차이로 2번 수집 (예: '개성집' / '개성집 공주점') | 실제 발생 유형 |
| 리뷰수 콤마 표기 | 6 | `"1,204"` → 문자열이라 정렬·계산 불가 | 화면 복사 시 실제 발생 |
| 별점 결측 | 5 | 별점 없는 플레이스 (리뷰 적은 곳) → **보정 알고리즘이 처리** | 실데이터 그대로 |
| 좌표 결측 | 1 | mapx/mapy 누락 → 지도에 못 찍음, 제외 판단 실습 | 주입 |
| 카테고리 미매핑 | 30행 전부 | 원문 그대로 → 매핑표로 통일 | 실데이터 그대로 |

**정제 정답: 33행 → 중복 2건 제거·좌표 결측 1건 제외 → 30행, 콤마 6건 숫자화, 카테고리 30건 매핑.**
이 숫자가 루브릭 '데이터 정제 20점'의 채점 기준이다.

## 5. 점수 알고리즘 (`scoring.py`) — 이 수업의 심장

### 5.1 보정 별점 — 베이지안 평균 ★손계산 차시

문제 제기부터 시작한다: **"리뷰 2개짜리 5.0점 카페와 리뷰 312개짜리 4.4점 베이커리, 어디가 진짜 맛집인가?"**

```
보정별점 = (v × R + m × C) ÷ (v + m)

v = 그 장소의 방문자리뷰 수
R = 그 장소의 별점            (별점 결측이면 R = C 로 두어 자연히 평균에 수렴)
m = 기준 리뷰 수 = 30 (전체 30곳 방문자리뷰 수의 중앙값에서 채택, 고정)
C = 전체 평균 별점 = 4.30    (시드 실측, init_db.py가 계산해 저장)
```

**손계산 검증 예제 (학생이 직접 푼다)**

```
카페 A   : v=2,   R=5.0 → (2×5.0 + 30×4.30) ÷ 32  = 139.0 ÷ 32  = 4.34
베이커리 B: v=312, R=4.4 → (312×4.4 + 30×4.30) ÷ 342 = 1501.8 ÷ 342 = 4.39

→ B 승리. "리뷰가 적은 별점은 전체 평균 쪽으로 끌려온다"
```

`verify.py`가 이 값이 코드 출력과 소수점 2자리까지 일치하는지 자동 확인한다.
`/stats` 화면은 **보정 전 랭킹 vs 보정 후 랭킹을 나란히** 보여주어 순위가 뒤집히는 장소를 강조한다 — 이 화면이 수업 데모의 클라이맥스다.

### 5.2 거리 점수 — "지금 여기서 가깝나"

지도에서 기준점(현재 보고 있는 장소, 또는 지도 중심)을 잡으면:

```
거리 점수 = 1 ÷ (1 + km)        # 하버사인 거리. 0km→1.0, 1km→0.5, 4km→0.2
```

하버사인 함수는 v2.4 확장과제 5의 `geo.travel_minutes()`를 그대로 재사용한다 (자산 재활용).

### 5.3 취향 부스트 — 클릭 로그로 배우는 암묵 피드백

폼으로 묻지 않는다. **행동이 곧 취향이다.**

```
카테고리별 관심도 = (그 카테고리 view 수 × 1 + fav 수 × 3) ÷ (전체 view×1 + fav×3)
취향 부스트     = 그 장소 카테고리의 관심도            # 0~1
로그 5건 미만이면 → 부스트 없이 균등(1/6)             # cold start, v2.4 폴백 개념 계승
```

"찜은 클릭보다 3배 강한 신호"라는 가중치 하나로 암묵 피드백의 핵심을 가르친다.

### 5.4 최종 점수와 정렬

```
final = 0.5 × (보정별점 ÷ 5) + 0.3 × 거리점수 + 0.2 × 취향부스트
```

가중치 3개는 지도 화면 상단에서 조절 가능(폼 재제출, v2.4 §6.3 방식 계승 — 이 부분은 JS 없음).
정렬을 바꾸면 **지도 마커 크기가 점수 순으로 커지고**, 우측 랭킹 목록이 다시 그려진다.

### 5.5 동선 정렬 (`route.py`) — 찜 목록을 걷는 순서로

코스를 "추천"하지 않는다. **학생이 찜한 곳을 정렬만 해 준다.** (v2.4와 역할 분담이 다른 지점)

```
① 찜 목록에서 가장 북쪽 장소를 출발점으로
② 남은 곳 중 가장 가까운 곳으로 이동 (최근접 이웃 탐욕법)
③ 반복 → 방문 순서 + 구간별 도보 시간(하버사인 × 1.3 ÷ 4km/h) 표시
④ 화면에 "이 방법은 최적해 보장이 없다"를 명시 — 탐욕 알고리즘의 한계도 교육 내용
```

## 6. 화면 설계

### 6.1 라우팅 7개

| 메서드 | 경로 | 화면/처리 | 핵심 요소 |
|---|---|---|---|
| GET | `/` | **지도 홈** | Leaflet 지도 + 마커 30개(점수순 크기), 카테고리 필터 칩 6개, 가중치 폼 |
| GET | `/panel/<id>` | 상세 패널 | 네이버플레이스 정보 카드: 별점·보정별점(비교 표시)·방문자/블로그 리뷰수·주소, [찜] 버튼 |
| POST | `/fav/<id>` | 찜 토글 | favorites INSERT/DELETE + clicks 로그 → 리다이렉트 |
| GET | `/favorites` | 찜 목록 | 찜 카드 + [동선 짜기] 버튼 |
| POST | `/route` | 동선 결과 | 순번 지도 + 구간별 도보 시간 목록 |
| GET | `/stats` | 대시보드 | **보정 전/후 랭킹 비교표**, 카테고리별 리뷰수 분포(CSS 막대), 내 클릭 로그 요약 |
| GET | `/offline` | SVG 폴백 지도 | 타일 로딩 실패 시 자동 안내 링크 |

### 6.2 지도 상호작용 — Leaflet 사용 범위를 못박는다

학생이 작성(프롬프트로 생성)하는 JS는 **map.html 안의 1블록**이 전부다:
지도 초기화 → 마커 찍기(서버가 Jinja2로 심어 준 JSON) → 마커 클릭 시 `/panel/<id>`로 이동.
팝업·애니메이션·AJAX는 쓰지 않는다. 패널·찜·동선·필터는 전부 **서버 렌더 + 폼 제출**이다.
"JS는 지도에만, 로직은 파이썬에만" — 이 경계가 디버깅 지옥을 막는다.

### 6.3 오프라인 폴백

타일 서버 접속 실패 시 화면에 "오프라인 모드" 배너와 함께 `fallback_map.svg`(좌표 산점도, v2.4 확장 3 방식)를 표시한다. `verify.py`가 인터넷 차단 상태에서도 전 라우트 200 응답을 확인한다.

### 6.4 디자인 규칙

지도가 화면의 70%, 우측(모바일은 하단) 랭킹 패널 30%. 색상 3개 이내, `style.css` 한 파일.
마커 크기 3단계(final 점수 상·중·하) + 카테고리별 색.

## 8. Claude Code 프롬프트 대본 (발췌)

**Step 2 — 정제**

```
data/places_raw.csv를 읽어 정제하는 scripts/preprocess.py를 만들어줘.
(1) 리뷰수의 콤마("1,204")를 제거해 정수로 변환
(2) 관광지명 중복 제거 (공백·지점명 차이 주의)
(3) 좌표(lat/lon) 결측 행은 제외하고 몇 행을 제외했는지 print
(4) category_map.csv를 읽어 category_raw를 표준 6분류로 매핑,
    매핑에 없는 원문이 나오면 오류 대신 목록으로 출력해줘 (내가 매핑표에 추가할 수 있게)
encoding='utf-8-sig' 고정. 줄마다 한글 주석.
```

**Step 4 — 보정 별점**

```
scoring.py에 adjusted_star(star, visitor_rev, m=30, C) 함수를 만들어줘.
(v×R + m×C) ÷ (v+m) 공식이고, star가 None이면 R=C로 계산해줘.
중간 계산(분자·분모)을 print로 보여줘. 넘파이 없이 순수 파이썬으로.
```

**Step 5 — 지도 마커**

```
map.html에서 Leaflet 지도를 띄우고 서버가 넘겨준 places JSON으로 마커를 찍어줘.
마커를 클릭하면 /panel/<id> 로 이동만 하면 돼. 팝업이나 애니메이션은 넣지 마.
leaflet은 static/leaflet/ 로컬 파일을 쓰고, 타일이 안 뜨면
"오프라인 모드" 안내와 /offline 링크를 보여줘.
```

(전체 대본은 v2.4 방식대로 교재 부록 제본 + `check_prompts.py` 정합성 검사 적용)
