# Claude Code 프롬프트 대본 — 맵으로 공주

> 학생은 아래 프롬프트를 **순서대로 복사해 입력**한다.
> 넣고 → 실행하고 → 오류가 나면 오류 메시지를 그대로 붙여 다시 물어보는 것까지가 한 세트다.
> **오류를 만나는 것이 실패가 아니다.** 그 루프가 이 수업의 3단계(생성형 AI 활용)다.

교사용 완성본은 이 폴더에 이미 들어 있다. 학생이 막히면 해당 파일을 보여 주면 된다.

## Step 0 — 서버 띄우기 (1차시)

```

## Step 4 — 보정 별점 ★핵심 차시 (5-6차시)

먼저 **손으로 푼다.** 코드를 만들기 전에 종이에 쓴다.

> 리뷰 2개짜리 5.0점 카페와, 리뷰 312개짜리 4.4점 베이커리.
> 어디가 진짜 맛집인가?
>
> ```
> 보정별점 = (v × R + m × C) ÷ (v + m)      m = 30,  C = 4.30
>
> 카페   : (2 × 5.0 + 30 × 4.30) ÷ 32  = 139.0  ÷ 32  = 4.34
> 베이커리: (312 × 4.4 + 30 × 4.30) ÷ 342 = 1501.8 ÷ 342 = 4.39
> ```

그다음에 코드를 만든다.

```
scoring.py에 adjusted_star(star, visitor_rev, m, C) 함수를 만들어줘.
(v×R + m×C) ÷ (v+m) 공식이고, star가 None이면 R=C로 계산해줘.
m과 C는 data/params.json에서 읽어와줘.
분자와 분모를 print로 보여줘. 넘파이 없이 순수 파이썬으로.
```

**내 손계산과 코드 출력이 소수 둘째 자리까지 같은지 확인한다.**
여기서 다르면 다음 단계로 넘어가지 않는다.

생각해 볼 것: 별점이 없는 곳은 R에 C를 넣는다.
그러면 결과가 **항상 정확히 C**가 된다. 왜 그런가? 리뷰가 500개여도 그런가?

## Step 5 — 정규화 · 거리 · 취향 (7차시)

```
scoring.py에 star_score(adj, adj_min, adj_max)를 추가해줘.
(adj - adj_min) / (adj_max - adj_min) 으로 0~1로 펴 주는 함수야.
```

> **왜 이걸 하나**: 보정 별점은 3.6~4.8 사이에 뭉쳐 있다.
> 그냥 5로 나누면 차이가 0.2밖에 안 나서, 가중치를 0.5로 줘도
> 거리 점수(0~1)에 완전히 눌린다. 두 차시 배운 게 화면에 안 나타난다.
> 대신 최하위가 0점이 된다 — 이게 정규화의 대가다.

```
scoring.py에 아래 두 개를 더 만들어줘.
(1) distance_score(km) = 1 / (1 + km)
(2) pref_boost(category, interests, log_count)
    관심도 / (관심도 + 1/6) 으로 계산하고,
    로그가 5건 미만이면 그냥 0.5를 돌려줘.
```

```
final_score(별점점수, 거리점수, 취향부스트, w)를 만들어줘.
w는 (0.5, 0.3, 0.2)이 기본이고, 합이 1이 아니면 합으로 나눠서 맞춰줘.
정렬할 때 동점이면 방문자리뷰가 많은 쪽, 그래도 같으면 id가 작은 쪽이 위로 오게 해줘.
```

> 동점 규칙이 왜 필요한가? 별점 없는 5곳은 보정 별점이 **정확히 똑같다.**
> 규칙이 없으면 새로고침할 때마다 순위가 바뀐다.

## Step 6 — 상세 · 찜 · 클릭 로그 (8차시)

```
/panel/<id> 화면을 만들어줘. 별점과 보정 별점을 나란히 보여주고,
방문자리뷰·블로그리뷰·주소도 표로 보여줘. [찜하기] 버튼은 폼 제출로 동작하게 해줘.
이 화면을 열면 clicks 테이블에 'view'를 기록하는데,
같은 사람이 같은 장소를 10분 안에 다시 열면 또 기록하지는 말아줘.
```

> 10분 제한이 왜 필요한가? 새로고침 몇 번으로 한 카테고리 관심도가
> 0.8까지 올라간다. 그러면 취향이 아니라 새로고침 횟수를 학습하게 된다.

## Step 7 — 동선 · 통계 (9차시)

```
route.py에 최근접 이웃으로 찜 목록을 정렬하는 함수를 만들어줘.
가장 북쪽 장소에서 출발해서, 매번 남은 곳 중 가장 가까운 곳으로 가면 돼.
구간마다 이동시간도 계산해줘 — 3km 이하는 걷는 속도 4km/h,
넘으면 차 속도 40km/h로 하고 직선거리에 1.3을 곱해줘.
화면에 도보인지 차량인지도 표시해줘.
```

> 왜 3km에서 나누나? 공산성에서 마곡사까지 14.7km다.
> 전부 도보로 계산하면 화면에 **"286분"**이 찍힌다. 아무도 안 믿는다.

```
/stats 화면을 만들어줘. 별점이 있는 장소만 가지고
보정 전 랭킹(별점순)과 보정 후 랭킹(보정별점순)을 나란히 표로 보여주고,
순위가 3계단 이상 바뀐 곳은 배경색을 다르게 해줘.
```
